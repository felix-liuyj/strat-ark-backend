# TradingAgents + Freqtrade Crypto Web 平台开发计划

## 一、项目定位

### 1.1 产品目标

构建一个完整的 Crypto AI Trading Web 平台，具备以下能力：

1. 多交易所账户接入与机器人管理。
2. 基于 Freqtrade 的策略回测、模拟盘、实盘交易。
3. 基于 TradingAgents 的多智能体市场分析、交易建议、风险解释。
4. 统一 Web UI 管理策略、行情、信号、订单、收益、风险、日志。
5. 支持用户级权限、配置中心、任务调度、通知告警。
6. 后续可扩展为 SaaS：多用户、多 Bot、多策略、多交易所、多模型。

### 1.2 核心定位

项目不是简单套用 FreqUI，而是：

- 将 **Freqtrade** 作为交易执行与回测引擎。
- 将 **TradingAgents** 作为 AI 投研、信号解释、策略辅助与风控决策层。
- 将 **FastAPI Backend** 作为统一业务中台。
- 将 **React / Next.js Web UI** 作为自定义产品体验层。

### 1.3 推荐产品定义

```text
项目名称：
AI Crypto Trading Web Platform

核心定位：
基于 Freqtrade 的量化交易执行平台，
结合 TradingAgents 的 AI 投研与风控辅助系统，
提供完整 Web UI 管理交易机器人、策略、回测、信号、风险和交易记录。

第一阶段不做完全 AI 自动交易，
而是做 AI 辅助决策 + Freqtrade 策略执行 + 风控拦截。
```

### 2.2 核心职责拆分

| 模块 | 角色 | 不建议混用的原因 |
|---|---|---|
| Freqtrade | 策略执行、回测、模拟盘、实盘下单、订单管理 | 它是交易执行引擎，不适合直接承担复杂产品 UI 和多租户业务 |
| TradingAgents API Service | 多智能体分析、行情解释、新闻/情绪/技术面判断、风险建议 | 它更适合作为独立 API 服务承载研究与决策辅助，不应嵌入主后端或直接无约束下单 |
| FastAPI Backend | 平台业务中台，封装 Freqtrade 和 TradingAgents | 统一权限、配置、任务、日志、计费、风控 |
| React Web UI | 自定义 UI/UX 产品层 | 避免直接暴露 FreqUI，做成完整 SaaS 体验 |

## 三、产品功能范围

### 3.1 MVP 版本功能闭环

```text
用户登录
→ 绑定交易所 API Key
→ 创建交易机器人
→ 选择策略
→ 导入交易对
→ 启动 dry-run 模拟盘
→ 查看 AI 分析
→ 查看交易信号
→ 查看收益与风险
→ 回测策略
→ 人工确认后切换实盘
```

### 3.2 第一版不建议实现的内容

MVP 不建议一开始做“完全自动 AI 下单”。

更稳妥的设计是：

```text
AI 负责分析和建议
Freqtrade 负责严格按策略执行
用户负责授权是否允许实盘
风控模块负责最终拦截
```

## 4.4 策略管理模块

### 策略来源

1. 系统内置策略。
2. 用户上传策略。
3. AI 辅助生成策略。
4. 策略模板配置生成。
5. 后续支持策略市场。

用户上传策略文件统一走 OSS 直传链路：`POST /common/oss/presign` 获取 PUT
预签名地址，前端直传后调用 `POST /common/oss/confirm` 确认 ACL。上传目录与扩展名
必须命中后端 `libs/upload_rules.py` 白名单；策略文件使用 `strategies` 目录，
报告、导出物、材料分别使用 `reports` / `exports` / `materials`，业务接口只保存
`publicUrl` 或对象路径，不保存 `uploadUrl`。

### 策略类型

| 类型 | 示例 |
|---|---|
| 趋势策略 | EMA / MACD / Supertrend |
| 震荡策略 | RSI / Bollinger Bands |
| 突破策略 | Donchian Channel / Volume Breakout |
| AI 辅助策略 | TradingAgents 生成信号解释，Freqtrade 负责执行 |
| 风控策略 | 最大回撤、单币种敞口、波动率过滤 |

### 策略管理 UI

页面：`Strategy Lab`

功能区：

1. 策略列表。
2. 策略详情。
3. 参数配置。
4. 版本管理。
5. 回测入口。
6. 启用到 Bot。
7. 策略源码查看。
8. 策略风险标签。

## 4.8 实盘交易模块

### 实盘启用流程

必须设计强确认流程：

```text
完成 dry-run
→ 完成至少一次回测
→ 通过风控检查
→ 用户确认 API 权限
→ 用户确认风险声明
→ 开启 Live Mode
```

### 实盘风控拦截

| 风控项 | 说明 |
|---|---|
| 单笔最大亏损 | 超过则禁止下单 |
| 每日最大亏损 | 达到后自动停机 |
| 最大持仓数量 | 超过则禁止新开仓 |
| 单币种最大敞口 | 防止集中风险 |
| 连续亏损次数 | 超过后冷却 |
| 重大新闻风险 | AI 标记后降低仓位或暂停 |
| API 异常 | 自动停机 |
| 交易所延迟 | 自动停机 |

展示：

6. 未完成订单。

## 4.9 风控中心模块

### 风控层级

```text
用户级风控
Bot 级风控
策略级风控
交易对级风控
订单级风控
AI 信号级风控
```

### 风控规则

| 规则 | 示例 |
|---|---|
| Daily Loss Limit | 单日亏损超过 3% 停止交易 |
| Max Drawdown Limit | 回撤超过 10% 停止策略 |
| Max Position Size | 单笔不超过账户 5% |
| Max Leverage | 最大 3x |
| Cooldown Period | 连续亏损 3 次暂停 6 小时 |
| News Risk Filter | 高风险事件前禁止开仓 |
| Volatility Filter | 波动异常时降低仓位 |
| Liquidity Filter | 成交量不足不交易 |

### UI 页面：Risk Center

```text

├── 账户风险
├── Bot 风险
├── 策略风险
├── 持仓风险

└── 风控触发记录
```

## 十二、风险点与处理方案

## 12.1 TradingAgents 不应直接下单

风险：

```text
LLM 可能产生不稳定判断；
输出可能受 Prompt、数据质量、模型温度影响；
不适合直接作为唯一交易依据。
```

处理：

```text
AI 只生成建议；
策略负责执行；
风控负责拦截；
用户负责授权实盘。
```

---

## 12.2 Freqtrade 多 Bot 管理复杂

风险：

```text
每个 Bot 都需要独立配置、日志、数据目录、API Server、策略文件。
```

处理：

```text
每个 Bot 独立容器；
每个 Bot 独立 volume；
统一由 Backend 编排；
禁止用户直接修改底层配置。
```

---

## 12.3 实盘交易责任风险

处理：

1. 默认 dry-run。
2. Live Mode 强确认。
3. 风险声明。
4. 单独风控模块。
5. 审计日志。
6. 紧急停止按钮。
7. 交易所 API 禁止提现权限。

---

## 12.4 数据源质量风险

TradingAgents 分析依赖行情、新闻、情绪、技术指标。若数据源不完整，AI 结论质量会下降。

处理：

```text
第一阶段只使用行情 + 技术指标；
第二阶段加入新闻；
第三阶段加入社交情绪；
第四阶段加入链上数据。
```

### 18.1 营销官网首页（Marketing Landing）— 新增独立页面

原计划未包含面向公众的营销首页。前端新增：

**后端需求**：营销页以静态/构建期内容为主；可选将首页文案与模块介绍做成可配置（CMS/系统配置）。CTA 与登录跳转无特殊后端依赖。

### 18.2 引擎管理 Engine Management — 新增管理员页面

原计划架构层有 `Freqtrade Orchestrator` 与 `TradingAgents API Service`，但**缺少面向管理员的引擎运维 UI**。前端新增：

- 将 Freqtrade 执行引擎与 TradingAgents API 服务作为**集群内独立服务**（Kubernetes 视角）管理，页面内 **双引擎 tab 切换**（Freqtrade 执行引擎 / TradingAgents 投研引擎），但 TradingAgents 的部署边界是 API 服务而不是 compose engine。
- 每个引擎包含：
  - **监控**（常驻）：服务头（镜像/版本/副本/Uptime/健康）、KPI、Pods 实例表（节点/状态/CPU/内存/重启/运行时长）、资源利用、依赖健康、托管 Bot 容器（Freqtrade）/ Agent 编排（TradingAgents 8 智能体）、实时服务日志。
  - **连接设置**（弹窗）：内网服务地址、健康检查路径、REST Token / API Key（掩码）、超时、重试、mTLS；Freqtrade 含交易所端点表，TradingAgents 含模型网关（provider/model/endpoint/key）。
  - **编辑配置**（弹窗）：镜像、期望副本（步进器）、CPU/内存限额、日志级别、重启策略、运行模式与守卫（默认 Dry-run、强制守卫、实盘需 2FA+风控）、自动伸缩 HPA、模型参数（temperature/max tokens/top-p/配额）、启用的 Agents。
  - **高级操作**（弹窗）：扩缩容、滚动重启、热重载、排空重调度、清空队列、拉取镜像重建；**危险区**：紧急停机、销毁并重建（均二次确认）。
- **仅管理员可见可访问**（见 18.4）。

**后端需求**：
- 引擎/集群编排服务（封装 K8s API 或容器编排）：读取 Deployment/Pod 状态、资源指标、依赖健康、服务日志。
- 配置读取与下发（镜像/副本/资源/HPA/运行模式守卫/模型参数）。
- 运维操作 API（scale / rolling-restart / reload / drain / clear-queue / redeploy / emergency-stop / teardown），**全部需管理员鉴权 + 二次确认 + 审计**。
- 连接凭证加密存储、不明文回显、测试连接。
- 新增数据/接口：`engines`（服务定义与状态）、`engine_ops`（运维操作记录）。

### 18.3 审计日志 Audit Log — 新增管理员页面

原计划有 `audit_logs` 表与 `Audit Log Service`，但**缺少审计查看 UI**。前端新增：

- 每条记录标注角色（admin / system / user）。

**后端需求**：审计服务写入不可篡改的链式签名（前后哈希链）；支持按类别 / 角色 / 时间 / 资源检索与分页；导出；写入覆盖所有敏感操作（引擎运维、实盘切换、风控变更、订阅变更、Key 撤销等）。

### 18.4 角色权限与多账号视角 — 细化（原 4.1）

前端落地了明确的**页面级权限 gating**：

- 角色：**管理员（admin）** 与 **普通用户（user，含订阅用户）**。
- 管理员额外可见并可访问 **引擎管理 + 审计日志**；普通用户（含订阅用户）这两页**侧栏隐藏 + 路由守卫重定向**到 `/dashboard`。
- 账号一律走真实注册流程（`/register`：显示名 + 邮箱验证码 + 密码）：邮箱命中管理员白名单（`ADMIN_EMAIL_SUFFIXES`）自动为管理员，否则为普通用户；普通用户购买订阅后 `plan` 升级为付费套餐。多账号演示 mock（三角色一键登录 / 种子账号）已移除。
- 鉴权抽象：`AuthProvider` / `useAuth` 暴露 `user`（role + plan）、`isAdmin`；会话由后端 JWT 双 token 签发，角色由后端身份决定。

**后端落地**：用户角色模型（user_type + plan）；页面级与操作级权限；引擎管理 / 审计日志接口强制管理员鉴权；JWT/Session 与前端 `useAuth` 对接。

### 18.5 订阅、套餐与计费 — 细化（原仅第四期"套餐权限/订阅支付"）

前端落地了完整的订阅体验（**模拟流程，绝不接入真实支付**）：

- **套餐定义** Free / Pro / Team：价格（月付 / 年付，年付省 2 个月）、特性清单、额度上限（交易机器人 / 策略 / 每月 AI 分析 / 回测）。

| 套餐 | 月付 | 机器人 | 策略 | AI 分析/月 | 实盘 |
|---|---:|---|---|---|---|
| Free | $0 | 1 | 3 | 20 | 否（仅 Dry-run） |
| Pro | $49 | 10 | 20 | 300 | 是·多交易所 |
| Team | $149 | 无限 | 无限 | 2000 | 是·团队协作·优先支持 |

- **定价页 `/pricing`**：三卡 + 月/年切换 + 升级/降级/当前方案 CTA（按当前套餐联动）。

- 升级 / 降级 / 取消均走**确认弹窗 + toast**，更新本地套餐状态并联动全局（侧栏身份标签、定价页、用量额度）。

**后端需求**：套餐 / 订阅 / 用量 / 账单模型；用量计量与**额度限制（超额拦截）**；订阅状态机（生效/续费/降级/取消）；第三方支付服务对接与发票（真实计费由后端 + 支付服务完成，前端不接触支付）；新增集合 `plans / subscriptions / usage_counters / invoices`。

### 18.6 国际化 i18n（中文 / English）— 细化（原仅第四期"多语言"）

前端落地了全站双语：

- 账户菜单语言切换（中文 / EN），**切换实时重渲染**全站。
- **共同 key 式 `t()`**：所有界面文案使用稳定语义 key，中文与英文各自独立维护，不允许以中文源串作为翻译 key。

**后端需求**：枚举 / 状态 / 错误码 / 套餐与用量类展示字段返回稳定 key 或结构化 code，不返回中文源串让前端二次映射；动态内容（如 AI 报告）语言可选。
