# StratArk 策舟 · 前后端接口契约

本文件是前端「需要后端提供数据的点」与后端 API 的权威映射，作为前端接线与
后端联调的单一事实源。前端类型（`src/types/*`）、API 封装（`src/api/*`）、后端
Form/Response 模型三者以本文为准对齐。

- 后端共 19 个业务域、141 条路由（另含 `common` 健康检查 / OSS 直传），已建好 `forms/` `responses/` `view_models/`。
- 前端已为**全部域**建契约层（`src/types/*` + `src/api/*`），且**所有页面均已接入真实 API**
  （含 OAuth Public PKCE 登录）；不再有内联演示数据源。下文各节「状态」统一为「已接」。
- 一致性核对（path + query + 字段，最近一次全量对拆）：前端每个 `apiClient` 调用都有后端
  对应路由（零 404 缺口）；query 参数名（snake_case）逐一匹配（含 bots 日志 `level`、audit
  `category/role/start_time/end_time/page_no/page_size`）；前端类型由后端 `responses.py` /
  `forms.py` 字段反推，逐字段对齐（含 dashboard 的 `risk` 键、各枚举值）。
- 后端可用但前端暂未接（均为可选、非缺口）：`GET /admin/users`（无管理员用户页）、
  `GET /backtests/{id}/result`（前端用更全的 `GET /backtests/{id}`）、`POST /notifications`（系统侧创建）。
- OSS 直传（头像已接，`src/api/oss.ts`）：`POST /common/oss/presign`（`directory`,`filename`,`contentType` →
  `objectKey`,`uploadUrl`,`publicUrl`,`fileUrl`,`ossPath`,`contentType`）→ 前端 PUT `uploadUrl`（带签名
  `Content-Type` 与 `x-oss-object-acl: public-read`）→ `POST /common/oss/confirm`（`ossPath`）。
  头像上传走 `avatars` 目录；`PUT /auth/profile` 的 `avatarUrl` 入库校验：空=置空、与现值相同=保持
  （兼容 OAuth 第三方头像），新值必须是当前 Bucket `avatars/` 下对象，OSS 未配置时拒绝换新头像。

## 一、全局约定

### 1.1 响应封装

后端统一返回 `BaseResponseModel[T]`：

```jsonc
{
  "category": "strat-ark-backend", // 应用标识，前端忽略
  "code": "0000",                  // 业务码，"0000" 为成功
  "message": "成功",
  "data": { /* T，失败时为 null */ }
}
```

前端 `src/types/api.ts` 的 `ApiResponse<T>` 只读 `code/data/message`；`src/api/_response.ts`
的 `unwrap()` 在 `code !== "0000" || data === null` 时抛 `message`。

业务码（`libs/response.py:ResponseStatusCodeEnum`）：`0000` 成功 / `0001` 空内容 /
`0002` 无变更 / `2000` 失败 / `2001` 参数非法 / `2002` 未登录 / `2003` 无权限 /
`2004` 不存在 / `2101-2106` 鉴权细分 / `3000` 系统错误。

### 1.2 命名与方法约定

- Body / Form / Response 字段一律 **camelCase**；Query / Path 参数 **snake_case**。
- 列表 GET 返回 `data: T[]`；分页域（audit）返回 `BasePaginationResponseDataType`
  （`total/pageNo/pageSize/hasMore/items`）。
- 资源级动作走 `/{resource}/{id}/{action}`（如 `/signals/{id}/approve`）。

### 1.3 鉴权

- 登录成功返回 `accessToken` + `refreshToken` + `user`，前端持久化后，业务请求带
  `Authorization: Bearer <accessToken>`。
- 401（`code 2002`）触发一次 `/auth/refresh` 后重试；刷新失败跳登录。
- 前端 `mapRole()` 把后端 `userType` 映射为 `admin/user` 再做菜单与路由权限。
- 公开端点（无需登录）：`/health`、`/market/*`（watchlist 除外）、`/plans`、
  `/auth/otp|register|login|refresh|password/reset`、`/oauth/exchange`。
- 管理员专属：`/engines/*`、`/engine-ops`、`/audit-logs/*`、`/admin/users`。

### 1.4 环境变量

- 前端：`VITE_API_BASE_URL`（指向后端，默认 `http://localhost:8000`）。
- 后端：`CORS_ORIGINS` 必须含前端来源。详见各自 `.env.example`。

| 数据点 | 方法 路径 | 请求（camelCase） | 响应关键字段 |

## 四、接线注意事项

1. **响应解包**：所有调用经 `unwrap()`，仅取 `data`；错误经 `message` 抛出，由页面 try/catch + Toast。
2. **路由缺参**：`/market-detail`、`/bot-detail` 当前无路径参数，接线需经 `?symbol=`、`?botId=` 或路由 state 传入，必要时改造为 `/bot-detail/:id`。
3. **量纲换算**：信号 `confidence` 0-1 ↔ 页面百分比；后端多数字段已给 `xxxLabel` 展示串，避免前端重复格式化。
4. **角色映射**：`userType` 必须经 `mapRole()` 再判定 admin；管理员页面同时受后端 `2003 forbidden` 兜底。
5. **写操作后刷新**：创建/启停/订阅变更等成功后，刷新对应列表与全局（未读通知、订阅用量）。
6. **掩码字段不回填**：交易所、引擎连接、渠道 config、LLM apiKey 回显为掩码，更新时掩码占位不覆盖已存值。
