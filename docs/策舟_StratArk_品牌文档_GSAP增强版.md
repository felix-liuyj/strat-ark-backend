## 二、品牌定位
策舟 StratArk 是面向加密资产交易场景的 AI 量化交易平台。产品以 Freqtrade 作为交易执行与回测引擎，以 TradingAgents 作为 AI 投研与多智能体分析层，并通过自定义 Web UI 将策略、信号、风控、回测和机器人管理整合为统一的产品体验。
品牌不强调投机性与短期暴利，而强调系统化决策、策略纪律、风险控制与可审计的 AI 辅助判断。
### 2.1 一句话定位
策舟 StratArk 是一个结合 AI 投研、多智能体分析与量化交易执行的加密资产交易平台。
### 2.2 对外介绍
策舟 StratArk 通过 AI 投研、策略回测、交易机器人与风控系统，为加密资产交易者提供从市场分析、策略验证到模拟盘和实盘执行的一体化工具。
### 2.3 核心价值

| 价值点 | 说明 |
| --- | --- |
| AI 投研 | 通过多智能体分析市场结构、技术面、情绪面和风险因素，形成结构化分析报告。 |
| 量化策略 | 基于可回测、可执行、可复盘的策略体系，减少主观交易干扰。 |
| 交易执行 | 封装 Freqtrade 的交易机器人能力，支持策略执行、模拟盘、实盘与日志追踪。 |
| 风险控制 | 通过独立风控中心限制亏损、回撤、仓位、杠杆和异常行情风险。 |
| 完整 Web 体验 | 将原本分散的策略、Bot、信号、日志、回测与 AI 报告统一到一个产品界面。 |


## 三、命名释义
### 3.1 中文名：策舟
“策”代表策略、决策、谋划与量化交易中的规则体系。
“舟”代表承载、航行与穿越波动市场的稳定工具。
“策舟”整体含义是：以策略为舟，依靠 AI 投研与量化系统，在高波动的加密市场中保持纪律性和方向感。
### 3.2 英文名：StratArk
StratArk 由 Strategy 与 Ark 组合而来。
“Strat”对应策略、量化、交易系统与决策逻辑。
“Ark”对应方舟、承载系统、风险中的稳定容器。
该名称适合表达一个集成 AI 投研、策略回测、交易执行与风控能力的完整交易平台。
### 3.3 品牌联想

| 关键词 | 品牌含义 |
| --- | --- |
| 策略 | 不依赖情绪交易，以规则和系统为核心。 |
| 方舟 | 面对市场波动时提供稳定承载。 |
| 航行 | 交易不是单点决策，而是持续穿越周期。 |
| AI 投研 | 用多智能体协作补充人的判断。 |
| 风控 | 将风险约束置于收益追求之前。 |

## 七、产品 UI 应用规范
### 7.1 首页 Dashboard
Dashboard 应优先呈现资产、收益、风险和 Bot 状态，帮助用户在打开产品后快速判断当前交易系统是否正常。
顶部显示 Total Equity、Today PnL、Active Bots、Risk Status。
中部显示权益曲线、回撤曲线与 AI 市场摘要。
底部显示最新信号、当前持仓和最近交易。
### 7.2 AI Research Room
AI Research Room 不应设计为普通聊天窗口，而应设计为结构化投研报告界面。
左侧：交易对、时间周期、分析类型。
中间：综合结论、置信度、入场区间、止损、止盈、摘要。
右侧：技术分析师、情绪分析师、多头观点、空头观点、风控经理。
底部：历史报告与信号记录。
### 7.3 Live Mode 风险表达
涉及实盘交易时，UI 必须显著区分 Dry-run 与 Live Mode。Live Mode 应采用风险红或警示橙标识，并在关键操作前进行二次确认。
启动实盘前展示风险声明。
策略参数修改需二次确认。
紧急停止按钮应固定展示。
API Key 不允许明文显示。
所有交易操作必须记录审计日志。
## 八、动效与 GSAP 应用规范
GSAP 适合用于策舟 StratArk 的官网、产品登录页、关键数据转场、AI 分析流程可视化和 Dashboard 微交互。动效应服务于“策略、航行、风险控制、系统可信度”的品牌表达，不应制造炫技感或干扰交易判断。
### 8.1 动效定位
动效目标是提升产品的高级感、引导用户理解复杂信息，并强化 AI 投研与量化执行的系统感。
动效风格应保持克制、精确、平滑，避免过快、过强、过度游戏化。
交易执行、风险警示、实盘确认等高风险场景，应优先保证清晰和稳定，不使用强烈动画遮挡关键信息。
### 8.2 推荐 GSAP 使用场景


| 场景 | 动效建议 | 使用边界 |
| --- | --- | --- |
| 官网 Hero | 使用 GSAP 做 Logo / Slogan 渐入、星图网格轻微移动、策略曲线描边动画。 | 首屏动效控制在 1.2-1.8 秒内，不影响核心文案读取。 |
| 登录页 | 背景可采用低速粒子、网格线、方舟轮廓或信号线轻微漂移。 | 登录表单保持稳定，不做抖动、旋转或复杂转场。 |
| Dashboard | 资产卡片、风险状态、收益曲线进入页面时做轻量 stagger 动画。 | 实时交易数据更新不应频繁闪烁，避免造成误判。 |
| AI Research Room | 多 Agent 分析流程可用 timeline 展示：技术面、情绪面、风险、最终结论依次生成。 | AI 输出结果需可读、可审计，不用动画替代内容。 |
| Backtest Center | 回测结果生成后，权益曲线、回撤曲线、指标卡片分段出现。 | 不得用夸张动效强化收益表现，避免误导。 |
| Risk Center | 风险等级变化可使用颜色过渡和轻微脉冲提示。 | 高风险告警必须静态可见，不能只依赖动画。 |

### 8.3 动效语言规范
速度：常规 UI 动效控制在 180-300ms，页面级转场控制在 500-900ms。
缓动：优先使用 power2.out、power3.out、expo.out；避免 bounce、elastic 等娱乐化效果。
节奏：使用轻量 stagger 呈现数据卡片和报告模块，形成“系统有序运行”的感受。
层级：品牌展示页可以适度增强动效，交易执行页和风控页必须克制。
可访问性：支持 prefers-reduced-motion，用户关闭动效后仍可完整使用产品。
### 8.4 页面级动效建议
官网首页：Hero 区可采用“方舟轮廓 + 策略曲线 + 星图网格”的组合动效，表达穿越市场波动。
产品首页 Dashboard：进入页面时先展示风险状态，再展示资产和收益，最后展示 Bot 与信号列表，强化风险优先原则。
AI 分析页：用 GSAP timeline 表达多智能体协作分析过程，但最终报告必须以结构化卡片稳定呈现。
回测结果页：回测完成后再触发结果动效，使用曲线绘制和指标卡片渐入，帮助用户理解结果构成。
Live Mode 页面：仅允许使用低强度状态变化动画。实盘启动、停止、紧急停止等按钮不得使用炫技转场。
### 8.5 前端实现建议
React / Next.js 项目中建议将 GSAP 封装为独立动效层，避免业务组件中散落复杂 timeline。动效组件应支持统一开关、统一时长、统一缓动和低动效模式。
建议目录：
frontend/├── src/│   ├── animations/│   │   ├── gsap.config.ts│   │   ├── timelines/│   │   ├── hooks/│   │   └── presets.ts│   ├── components/│   ├── pages/│   └── styles/
### 8.6 GSAP 品牌动效示例
import gsap from "gsap";export function playHeroIntro() {  const tl = gsap.timeline({ defaults: { ease: "power3.out" } });  tl.from(".brand-logo", { opacity: 0, y: 16, duration: 0.6 })    .from(".brand-title", { opacity: 0, y: 20, duration: 0.6 }, "-=0.3")    .from(".brand-slogan", { opacity: 0, y: 16, duration: 0.5 }, "-=0.25")    .from(".hero-metric-card", {      opacity: 0,      y: 18,      duration: 0.45,      stagger: 0.08,    }, "-=0.15");  return tl;}
